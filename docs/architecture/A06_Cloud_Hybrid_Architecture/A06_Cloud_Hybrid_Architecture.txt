```
              TOPIC 127 — CLOUD / HYBRID ARCHITECTURE
   Current EC2 Implementation • Edge/OT Placement • Cloud Evolution • Hybrid Target
```

========================================================================================================================

IMPORTANT ARCHITECTURE RULE

A06 describes:

• WHERE the current Topic 127 platform is deployed
• HOW the current EC2 implementation can evolve toward a hybrid architecture
• WHICH workloads should remain close to the manufacturing / OT environment
• WHICH workloads can be centralized in a future cloud platform
• The boundary between CURRENT IMPLEMENTATION and FUTURE TARGET

A01 = functional system architecture
A02 = network / deployment placement
A03 = data movement / information flow
A04 = operational process / workflow execution
A05 = security controls / trust boundaries
A06 = current EC2 implementation → future cloud / hybrid evolution

IMPORTANT:

A06 does NOT replace A01–A05.

A01–A05 remain authoritative for their respective architectural concerns.

20. ARCHITECTURAL LIMITATIONS
=============================

The current repository is intentionally an educational / simulated
proof-of-concept environment.

Current limitations include:

• Single EC2 host
• Software-simulated industrial equipment
• Software-simulated cleanroom sensors
• Host-side industrial protocol simulators
• Docker Compose rather than Kubernetes
• Demonstration-oriented external endpoints
• Controlled rather than continuous Suricata monitoring
• Separate executable ML demonstrations
• Rule-based Custom Edge AI
• Local persistence rather than managed cloud storage
• No production multi-site deployment
• No implemented cloud disaster-recovery architecture
• No implemented multi-AZ application architecture
• No implemented enterprise cloud identity platform

These limitations are intentional and must not be interpreted as
missing components of the current proof-of-concept.

FINAL POSITION:

The Topic 127 repository currently implements a single-host AWS EC2
educational platform using Docker Compose and host-side Python services.

A06 defines a controlled architectural evolution toward a hybrid model
in which latency-sensitive industrial, safety and Edge AI functions
remain close to the OT environment while centralized analytics,
long-term storage, security operations, governance and evidence
management can evolve into a central cloud platform.

The future hybrid architecture is a TARGET ARCHITECTURE only.

No unimplemented AWS managed service, Kubernetes platform, multi-site
deployment, high-availability topology or enterprise cloud control is
represented as currently implemented.
