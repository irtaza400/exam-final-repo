   These ports are documented for the examination / demonstration environment.
   They should NOT be interpreted as a recommended production security-group design.

   Production deployment should use:
   • restricted source IP ranges
   • private networking where possible
   • segmentation between OT and IT
   • strong authentication
   • encrypted communications where supported
   • least-privilege network access

LEGEND
Dockerized service = Service running inside Docker Compose
Host Service       = Python process / project component running on EC2 host
:PORT              = Network endpoint / exposed service port
↓                  = Processing / communication flow
►                  = Network routing direction
BOUNDARY           = Logical deployment / trust boundary
*                  = Optional security-demo profile

IMPORTANT:
Mosquitto is a MESSAGE BROKER and therefore provides publish/subscribe
communication rather than acting as a single sequential pipeline stage.
The implemented cleanroom telemetry architecture contains two primary
MQTT processing paths from the raw telemetry topic:

topic127/raw/cleanroom
  ↓
MQTT → InfluxDB Ingestion
  ↓
InfluxDB
  ↓
Grafana

topic127/raw/cleanroom
  ↓
Edge Gateway
  ↓
topic127/edge/validated
  ↓
Edge AI / ML Analysis
  ↓
Anomaly / Alert

FUXA is represented as a separate operational HMI path to host-side
industrial / OPC-UA services and is NOT shown as a downstream consumer
of InfluxDB.
The architecture reflects the CURRENT EDUCATIONAL DEPLOYMENT MODEL and does
not claim to represent a production semiconductor fabrication network.
